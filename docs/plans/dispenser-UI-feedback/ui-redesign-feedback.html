Dispenser Touchscreen — Elderly-Friendly Redesign

visual report · source: ui-redesign-feedback.md · ESP32-S3 + LVGL 9.2.2 · NV3041A 480×272 · GT911 touch

Overview

This redesign keeps every feature the current firmware already has and makes it elder-friendly: a light high-contrast theme, body text that's actually legible at this screen's pixel density, plain wording, bigger touch targets, and a flatter path to the daily task. It does not remove features or invent new hardware behaviour.

Where the redesign adds something beyond today's UI — a number pad instead of the +/- stepper, medicine colour identity, on-screen Dispensing→Done→Failed states, audio feedback — it is tagged IMPROVEMENT so current-vs-proposed stays unambiguous. The feature-coverage matrix shows where each existing feature lives in the new design. Everything is buildable on the existing LVGL 9.2.2 stack (see Feasibility).

Findings

Severity: P0 blocks the task or is a safety issue · P1 major friction · P2 polish.

P0Pill count is entered with two tiny arrows

In ui_RefillScr.c the count uses an lv_spinbox with +/− buttons 32×32 px (6.3 mm), step ±1, no typing. Loading 30 pills can take up to 30 precise taps — very hard with a tremor, and over-shoot means tapping back.

P0Dark, low-contrast theme

Every screen is light text on black. Older eyes read best with high contrast, ideally dark text on a light background. The current scheme is the worst case for this audience.

P0Text is below the legibility floor

Body text is montserrat_16 ≈ 9 pt physically — roughly half the 16 pt minimum for seniors. Reaching 16 pt means ~28 px body.

P0A voice/auto-triggered dispense shows nothing on screen

A dispense command (incl. the voice box's 5A A5 01 00 on 0xFFB2) acts, but the on-screen "Dispensing…" message is commented out at lvgl_ui.c:1543-1547 — only a buzzer fires. The elder gets no reliable confirmation the machine acted. Safety gap.

P0Engineer wording and typos

"Pls enter the number of pills…", "MEDICATION REMIND", "Rebooting…", "Transport pills", "Pill numbers: Not specified", "ACCOUNT INFOMATION" (typo). Jargon and broken grammar make the device feel untrustworthy.

P1Vitals are split across two passive screens

Blood pressure (ui_BLEDeviceScr.c) and ECG/patch (ui_ECGScr.c) are separate screens, each a dense read-out. For a quick "how am I doing?" glance they should be one calm dashboard.

P1Medicines are labelled "Option 1 / 2 / 3"

The lists show generic indices, not the drug name, colour, and shape. Elders identify pills by recognition cues, not list position.

P1Dense, multi-level dispenser menus

Reaching refill is Home → Dispenser → Menu → Medications → Refill → Confirm, and "Back" is a 40 px corner arrow. The redesign flattens entry points onto Home.

P2Weak feedback + an unimplemented button

speaker.c plays only a placeholder tone (no click/chime); and "Transport pills" (transportAct) is an empty handler — it does nothing. Either implement it or hide it so it doesn't mislead.

Icons — used more, and grounded in what the stack provides

LVGL's built-in symbol font (verified in lvgl/…/lv_symbol_def.h) covers UI chrome only — there is no heart or pill glyph. So the redesign uses LVGL symbols for status/controls and reuses the firmware's existing custom PNGs (ui_img_medicine, ui_img_medication, ui_img_user, ui_img_setting…) for medical concepts. Icons appear consistently in a status bar, on every list row, and beside every action.

Feasibility on ESP32-S3 + LVGL

Verified against the vendored LVGL v9 source. Every element maps to a standard widget already in the firmware's lvgl__lvgl component, renders within RGB565, and avoids effects the MCU can't draw cheaply.

SuggestionLVGL v9 building blockCost / limitsFeasible?
Number padlv_buttonmatrixOne widget + button map; big cells via style. Trivial RAM.YES
Light theme, body ≥ 28 pxlv_style / lv_themeFlat fills RGB565-safe. Keep ~3 font sizes to bound flash.YES
Big buttons + tiles, list rowslv_button · lv_list · lv_labelPlain objects; no shadow/blur inside the screen.YES
Dispensing → Done / Failedlv_label · lv_bar · lv_objPath already exists (commented lvgl_ui.c:1543).YES
Vitals dashboard panelslv_obj grid + lv_labelPassive; just lays out values already received over BLE.YES
Status-bar + list iconsLV_SYMBOL_* (built-in font)Wi-Fi/BT/battery/bell/settings free in the symbol font; medical icons reuse existing PNGs.YES
Medicine colour identitylv_obj swatch + lv_labelColoured rounded obj cheaper than an image. Data in prescription.c.YES
Help QR (About)lv_image (qrcode component)Firmware already vendors espressif__qrcode; cache the buffer.YES
Tap click + chimesI²S via speaker.cShort PCM clips, a few KB each.YES
Screen transitionslv_screen_load_animSimple fade/slide only — no per-frame blur on the S3.LIGHT ONLY
Touch At 128 ppi a 56 px row is 11 mm and a 54 px button is 10.7 mm — above the ~10 mm senior minimum. GT911 is capacitive (light taps); the design uses no swipe/long-press as a required action.
