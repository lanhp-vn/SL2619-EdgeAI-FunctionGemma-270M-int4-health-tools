# Dispenser Touchscreen UI — Elderly-Friendly Redesign Feedback & Spec

**Subject:** UX review + redesign spec for the ESP32-S3 medication-dispenser touchscreen
**Reference firmware:** `docs/references/upstream/Dispenser_LCDTouch_V2` (read-only submodule)
**Voice path:** `scripts/dispenser_demo/deploy/dispenser_voice.py` (SL2619 voice box → BLE → dispenser)
**Deliverable type:** Design spec only — *no edits to the firmware submodule*. Firmware devs implement from this.
**Author hats:** (1) an elderly user who can use a phone but struggles with fiddly UIs, (2) a UI/UX engineer for this exact board.
**Status:** DRAFT for review.
**Companion visual report:** [`ui-redesign-feedback.html`](ui-redesign-feedback.html) — to-scale 480×272 mockups for every screen in the redesigned flow (§4.2), an interactive flow diagram, and the feasibility table. Generated by the `/generate-visuals` skill from this doc; regenerate after edits to keep them in sync.
**Widget naming:** LVGL **v9** canonical names throughout (firmware is 9.2.2). v8-era aliases (`lv_btn`/`lv_img`/`lv_btnmatrix`/`lv_scr_load_anim`) still compile but the v9 names (`lv_button`/`lv_image`/`lv_buttonmatrix`/`lv_screen_load_anim`) are authoritative — verified against the vendored `docs/references/upstream/ESP-UI-Display/lvgl` source.
**Screen sizing:** the HTML mockups are **fit-first** — every screen fits 480×272 with no scroll by keeping the primary action and hero numbers large and trimming secondary text to ~20–24 px. This is the honest trade-off the small panel forces (see §1.1).

> **⚠ Faithfulness corrections (codebase audit) — supersede earlier framing below.** (1) **Settings are on-device, not in a phone app.** Date/Time, Account (view + Remove), About (two firmware updates + Factory reset + Help QR), Network reset, Offline mode, and Download/Delete prescription all run on the device; **only Wi-Fi *setup*** is delegated to the phone app (`ui_PairScr.c`). The redesign **keeps all of these on-device** and restyles them. (2) **Vitals screens are passive read-outs.** The dispenser does command the BP cuff (`b180_sendStart`) and ECG patch (`start_ecg`) over BLE, but there is **no on-screen measure/action button** today, so the redesign adds none — vitals become a single passive dashboard. (3) **No caregiver-PIN gating** is introduced (it does not exist in firmware). Any PIN/lock is out of scope. The companion **[`ui-redesign-feedback.html`](ui-redesign-feedback.html)** is the authoritative, faithful screen set (one redesigned mockup per current screen + a feature-coverage matrix). Where this markdown's §4.2 / §5.6 still describe a PIN-gated caregiver split, treat the HTML as correct.

## 0. TL;DR

The current UI is an engineer's build: a deep tree of 22 screens, a dark low-contrast theme, sub-10 pt text, jargon wording, and a pill-count entry that can require **dozens of taps on a 6 mm target**. For an elderly daily user it is genuinely hard.

The biggest unlock keeps **every existing feature** but makes the device legible and plain-spoken — a light high-contrast theme, readable body text, plain wording, bigger targets, and a flatter path to the daily task. (A codebase audit confirms all settings already run on-device; only Wi-Fi *setup* is delegated to the phone app, so the redesign restyles settings rather than removing them.) Rebuilt around one rule:

> **One task per screen. One obvious thing to touch. Words a 75-year-old reads once and understands.**

Headline changes:

1. **Flatten** the tree from 5+ levels to **≤2** for every daily task.
2. **Home = "what's due now" + one giant Dispense button.** Nothing else competes.
3. **Kill the +/- stepper** for refill; replace with a **big number pad / preset buttons** (range is only 0–30).
4. **Light, high-contrast theme** (dark text on light) and **body text ≥ 28 px** (≈16 pt).
5. **Identify medicines by name + colour + shape**, never "Option 1/2/3".
6. **Voice as a first-class accessibility input** — and, because the BLE link is *one-way*, the **device's own screen must independently show Dispensing → Done / Failed** (today it shows nothing for a voice dispense; the code is commented out).
7. **Plain-language wording sweep** (table in §11).

Keep the existing **LVGL 9.2.2** stack; the redesign is theme + layout + wording, not a framework change.

### 1.1 The core tension: px vs physical size

LVGL sizes are **pixels, not points**. On a 128 ppi panel the physical sizes are small:

| LVGL size                                       | px | em height (mm) | ≈ point size    | Verdict for elderly              |
| ----------------------------------------------- | -- | -------------- | ---------------- | -------------------------------- |
| `montserrat_16` (current body)                | 16 | 3.2 mm         | **~9 pt**  | ✗ ~half the recommended minimum |
| `montserrat_20` (current lists/buttons)       | 20 | 4.0 mm         | ~11 pt           | ✗ still under                   |
| `montserrat_26` (current spinbox value)       | 26 | 5.1 mm         | ~15 pt           | borderline                       |
| **`montserrat_28` (proposed body min)** | 28 | 5.5 mm         | **~16 pt** | ✓ meets "16 pt+ body"           |
| `montserrat_36`                               | 36 | 7.1 mm         | ~20 pt           | ✓ headings                      |
| `montserrat_48` (proposed clock/primary)      | 48 | 9.5 mm         | ~27 pt           | ✓ hero numbers                  |

**Touch targets** (capacitive, fingertip): seniors need **≥ ~9–10 mm** physical = **≥ ~50 px**. The current refill +/- buttons are **32 px = 6.3 mm** — too small, and they must be hit repeatedly.

**Consequence:** at 480 × 272 with legible type, **you can only fit ~5–6 lines of body text or 2–3 big buttons per screen.** This is *why* "one task per screen" is not a nicety here — it's forced by physics. Every screen below is budgeted against this.

## 3. Design principles (for this device, this user)

Derived from the seniors-healthcare guidance (orangesoft) intersected with the 480×272 reality:

1. **One task per screen.** If a screen answers more than one question, split it.
2. **The primary action is the biggest thing on screen.** Full-width button bar, ≥ 64 px tall.
3. **Dark text on light background.** Contrast ≥ 7:1 (WCAG AAA). Reserve red/green only as *redundant* cues paired with words + icons (colour-blind safe).
4. **Body text ≥ 28 px (~16 pt). Hero numbers 48 px.**
5. **≤ 2 levels deep** for every daily task. Persistent, *labelled* "Back" (text + arrow), ≥ 56 px.
6. **Plain words, second person, present tense.** "Take your morning pills" not "Dispense scheduled dose".
7. **Recognition over recall.** Show medicine name + colour swatch + time; never an index.
8. **Confirm every action** with a big visual + a sound (and optional voice readback).
9. **No dead ends, no silent states.** Every long operation shows progress → result.
10. **Caregiver/danger functions live behind a PIN**, off the elder's main path.

## 4. Information architecture — old vs new

### 4.1 Current (daily + config tangled, deep)

```
Splash → MainHome(idle) → Home1
   ├─ DISPENSER → DispenserMenu ─┬─ Medications → RefillScr → ConfirmScreen
   │                             ├─ Doses (DoseScr: All / Missed tabs)
   │                             └─ Management (Download / Transport / Delete)
   ├─ ECG SENSOR → ECGScr
   └─ (gear) SettingMenu ─┬─ Network (PairScr)
                          ├─ Date & Time (SetDateTimeScr)
                          ├─ Account info (AccountScr: Remove account)
                          └─ About (AboutScr: FW update, Factory reset)
   Reminders: DoseAlert.  Vitals: BLEDeviceScr (BP).  Errors: SysAlert / Alert.
```

### 4.2 Proposed (elder path flat; caregiver path gated)

```
ELDER PATH (no PIN, ≤2 levels):
  HOME (idle)  ── shows next dose + big [ TAKE MY PILLS ] + 2 tiles (Health, My Meds)
     │
     ├─ [TAKE MY PILLS] / dose-due alert ─→ DISPENSING… ─→ DONE ✓  (or  COULDN'T DISPENSE ✗ → Get help)
     │
     ├─ HEALTH  ─┬─ Blood pressure (last reading, big)
     │           └─ Heart / ECG (status, big)
     │
     └─ MY MEDS ─┬─ medicine list (name + colour + time + "pills left")
                 └─ [ ADD PILLS ]  ─→ pick medicine ─→ number pad ─→ DONE ✓
                                       (was: RefillScr stepper + ConfirmScreen)

CAREGIVER PATH (behind PIN / long-press gear, mostly punts to phone):
  SETTINGS ─┬─ "Most settings are in the phone app" (with QR)
            ├─ Wi-Fi status (read-only) + Reset Wi-Fi
            ├─ Date & time
            ├─ Account (incl. Remove account)  ← danger, double-confirm
            └─ About / Update / Factory reset   ← danger, double-confirm
```

Net: the elder sees **3 things on Home** and never more than **2 taps** from any daily task. Everything scary is behind the PIN.

## 5. Per-screen wireframes (480 × 272, ASCII at ~proportion)

ASCII boxes are ~1:1.76 to mirror the panel. `[[ ... ]]` = full-width primary button (~64–80 px tall). Colour notes in *italics*.

### 5.1 HOME / idle — "what's due now"

Replaces `MainHome` + `Home1`. *Light background, near-black text.*

```
┌──────────────────────────────────────────────┐
│  Good morning, David            10:20  Thu    │  ← greeting + clock (clock 48px)
│                                                │
│   ⏰  Next pills at 11:00                       │  ← next-dose line, 28px bold
│       Blood pressure pill (white, round)       │  ← name + colour + shape, 28px
│                                                │
│   ┌──────────────────────────────────────┐    │
│   │        TAKE MY PILLS NOW             │    │  ← full-width, ~80px, high-contrast
│   └──────────────────────────────────────┘    │
│                                                │
│   [  ❤  My Health  ]      [  💊 My Meds  ]      │  ← 2 tiles, ~64px tall, labelled
└──────────────────────────────────────────────┘
```

- If nothing is due: the big button becomes calm/disabled with "All done for now ✓ — next pills at 8:30 PM".
- The gear/settings entry is **not** on this screen — it's a long-press on the clock or a small corner icon that opens the PIN pad.
- "No next doses" / "Sync time…" (current jargon) → "All done for now" / hidden (sync is silent).

### 5.2 DOSE DUE / TAKE PILLS

Replaces `DoseAlert` ("MEDICATION REMIND" / "Time to take"). Fired by schedule *or* a voice command.

```
┌──────────────────────────────────────────────┐
│   ⏰  Time for your pills                       │  ← 36px
│                                                │
│      Blood pressure pill                       │  ← name 32px
│      ● white  ○ round   •  1 pill              │  ← colour/shape/count cues
│                                                │
│   ┌────────────────────┐  ┌─────────────────┐ │
│   │   TAKE NOW         │  │   NOT YET       │ │  ← 2 big buttons; "NOT YET" not "SKIP"
│   └────────────────────┘  └─────────────────┘ │
└──────────────────────────────────────────────┘
```

- "SKIP" → "NOT YET" (gentler, less final). "DISPENSE" → "TAKE NOW".
- Reminder also rings + (optional) speaks: "It's time to take your blood pressure pill."

### 5.3 DISPENSING → DONE / FAILED  (NEW — closes gap P8)

This is the **most important new flow** because the BLE voice link is one-way (the voice box says "dispensing now" *before* the machine confirms — see §9). The **device's own screen must be the source of truth.**

```
 (1) IN PROGRESS                         (2a) SUCCESS
┌──────────────────────────────┐   ┌──────────────────────────────┐
│        Dispensing…            │   │          ✓  Done              │
│                               │   │                               │
│      ◐  please wait           │   │   Your pills are ready.       │
│   ████████░░░░░░  (spinner)   │   │   Please take them now.       │
│                               │   │                               │
│   Blood pressure pill         │   │   [[      OK, GOT IT      ]]   │
└──────────────────────────────┘   └──────────────────────────────┘

 (2b) FAILURE  (reuse existing UI_EVT_SCREEN_ALERT / error path)
┌──────────────────────────────────────────────┐
│   ✗  We couldn't give your pills              │  ← plain, not "Failed to dispense"
│                                                │
│   The tray may be empty or stuck.              │
│                                                │
│   ┌────────────────────┐  ┌─────────────────┐ │
│   │   TRY AGAIN        │  │   STOP          │ │  ← maps to current OK=manual dispense / CANCEL=quit
│   └────────────────────┘  └─────────────────┘ │
```

- Today: `lvgl_ui.c:1543-1547` has the "Dispensing medications…" alert **commented out**. Recommendation (firmware): wire (1)→(2a/2b) for *all* dispense triggers (touch, voice, cloud) — they already converge on `process_dose_dispense`, so one change covers all.

## 6. Pill-count entry — options with recommendation

Range is **0–~30, typed** (confirmed). Three candidates:

| Option                                  | What it is                                                        | Pros                                                                                      | Cons                                                                               |
| --------------------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **A — Number pad (RECOMMENDED)** | `lv_buttonmatrix` 0–9 + ⌫ + DONE, big keys (§5.4)               | Familiar (like a phone keypad / ATM); any value in ≤2 taps; large targets; no over-shoot | Two-step (pick medicine, then count) — but that's clearer anyway                  |
| **B — Preset buttons**           | Big buttons:`7  14  28  30  Other…`                            | Fewest taps for common pack sizes; dead simple                                            | Needs an "Other" fallback → still needs a pad; presets must match real pack sizes |
| **C — Big +/- with accel**       | Keep stepper but 64 px buttons, long-press acceleration, ×5 jump | Smallest code change; in-place                                                            | Still many taps; long-press is itself a senior-unfriendly gesture; over-shoot      |

**Recommendation: Option A (number pad), with Option B presets layered on top if the caregiver app reports the prescription's pack size.** i.e. show `30  90  Other…` first; "Other…" opens the pad. This gives one-tap for the common case and a friendly fallback. Avoid C — the stepper is the root complaint.

LVGL note (v9): a `lv_buttonmatrix` with a `map` of `"1","2","3","\n",...` and `LV_BUTTONMATRIX_CTRL` for sizing gives big keys cheaply; the value displays in an `lv_label`, not an editable `lv_textarea`, to avoid the on-screen cursor/keyboard. (Firmware is LVGL 9.2.2; v8-era names like `lv_btnmatrix` still resolve via compat aliases but the canonical v9 names are used here.)

## 7. Voice integration design (accessibility input)

The voice box (`dispenser_voice.py`) is a **separate SL2619 Linux device** that listens ("Hey Jarvis" → VAD → CrispASR → FunctionGemma) and, on a dispense intent, **notifies the dispenser** `5A A5 01 00` on `0xFFB2`. Roles: SL2619 = BLE *peripheral*, ESP32 dispenser = *central* (`gattc.c:3025/2795/5416`).

**Key facts that shape the UI:**

1. **The link is one-way.** The dispenser sends *nothing* back. The voice box says its canned line ("Your medication is being dispensed. Please check the dispenser.") **before** the motor confirms.
2. **So the screen is the only honest status.** Voice = the *input*; the **touchscreen §5.3 Dispensing→Done/Failed flow is the feedback channel.** A voice-triggered dispense MUST drive the same on-screen progress→result as a touch dispense. (Today it drives only a buzzer — P8.)
3. **Recognition cue for voice.** When a voice command arrives, show a brief "Heard you — getting your pills" banner so a hard-of-hearing elder *sees* that the spoken command landed.

**Design recommendations:**

- **Voice as equal alternative, not replacement.** Every voice action has a touch equivalent and vice-versa. Elders who can't tap reliably can speak; elders who can't hear/speak can touch.
- **On-device "voice is listening" indicator** (small mic glyph on Home) so the elder knows the feature is live — but voice STT runs on the SL2619, not the ESP32, so this is a status the voice box would need to surface (future two-way; see §10).
- **Failure honesty:** if the dispense fails after a voice command, the *screen* shows §5.3 (2b) "We couldn't give your pills → GET HELP". Do not rely on the voice box, which already "promised" success.
- **(Future) two-way ack:** adding a writable/notify-back characteristic so the dispenser can tell the voice box "done/failed" would let the voice say the truthful result. Out of scope for v1 but noted in §10.

## 8. Component & design-token guide (the LVGL theme)

Target: a reusable theme so every screen is consistent. All sizes in **px (physical mm)**.

### 8.1 Typography (Montserrat or a single non-condensed sans)

| Token        | LVGL font               | px (mm)  | Use                                                                                           |
| ------------ | ----------------------- | -------- | --------------------------------------------------------------------------------------------- |
| `hero`     | montserrat_48           | 48 (9.5) | clock, BP/heart numbers                                                                       |
| `title`    | montserrat_36           | 36 (7.1) | screen titles                                                                                 |
| `body`     | **montserrat_28** | 28 (5.5) | all body text —**floor**                                                               |
| `button`   | montserrat_28–32       | 28–32   | button labels                                                                                 |
| ~~caption~~ | —                      | —       | avoid going below body; if unavoidable, montserrat_24 (4.8 mm) and only for non-critical text |

Use **one** typeface. **Bold** for emphasis, never italics. Never lay text over a busy image.

### 8.2 Colour & contrast (light, high-contrast)

| Token       | Value                                     | Contrast       | Note                           |
| ----------- | ----------------------------------------- | -------------- | ------------------------------ |
| `bg`      | `#FFFFFF` / very light `#F5F5F5`      | —             | light background               |
| `text`    | `#1A1A1A`                               | 21:1 on white  | near-black body                |
| `primary` | `#0B5FA5` (deep blue) fill, white text  | ≥ 7:1         | primary action buttons         |
| `success` | `#1B7F3B` + ✓ + word "Done"            | ≥ 4.5:1 large | always paired with icon + word |
| `danger`  | `#B3261E` + ✗ + word                   | ≥ 4.5:1 large | always paired with icon + word |
| `tile`    | light card on`bg`, 1 px `#CCC` border | —             | Health / Meds tiles            |

Rule: **colour is never the only signal** — pair with icon + text (colour-blind / cataract safe). Offer an optional night mode (white-on-black) for low light, but default to dark-on-light.

### 8.3 Touch targets & layout

| Token                       | Value                                      | Note                       |
| --------------------------- | ------------------------------------------ | -------------------------- |
| Primary button              | full-width,**≥ 72 px** tall (14 mm) | one per screen             |
| Secondary button            | **≥ 64 px** tall (12.7 mm)          | max 2 side-by-side         |
| List row / key              | **≥ 56 px** tall (11 mm)            | meds list, number pad      |
| Back button                 | text "Back" + arrow,**≥ 56 px**     | top-left, every sub-screen |
| Min spacing between targets | **≥ 12 px** (2.4 mm)                | prevent mis-taps           |
| Screen margin               | 12–16 px                                  | breathing room             |

### 8.4 Feedback

- **Every tap** → short confirmation tone (replace the `speaker.c` placeholder sine with a soft click ~50 ms) + visual press state (button darkens).
- **Every completed action** → big visual (✓) + a distinct chime + optional spoken readback.
- **No auto-dismiss < 10 s** for any message the elder must read.

## 10. Library leverage (corrected for the real NV3041A QSPI panel)

The three submodules under `docs/references/upstream/ESP-UI-Display/`:

| Library                                             | Verdict                          | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------- | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ESP32_Display_Panel** (esp-arduino-libs)    | **Reference, not drop-in** | Official Espressif driver+LVGL-port layer with board profiles.**But** its 480×272 profile (VIEWE) is **ST7262 RGB**, while *this* board is **NV3041A QSPI** — a different bus/controller. Use it as the **LVGL-port pattern** (init → flush callback → tick) and for its ESP32-S3 buffer guidance; don't assume a ready-made profile for JC4827W543. The current firmware already drives NV3041A via `Arduino_GFX`. |
| **roo_display** (dejwk)                       | **Reference only**         | Gorgeous anti-aliased 60–90 px fonts + zero-flicker rendering — instructive for big legible type — but it's a*canvas*, not a widget toolkit. Swapping off LVGL would mean re-building buttons/lists/keypads by hand. Not worth it.                                                                                                                                                                                                             |
| **ESP32-Cheap-Yellow-Display** (witnessmenow) | **Skip**                   | Docs/examples for a 320×240 resistive board. Wrong hardware. (Its LVGL8/LVGL9 port examples are a minor reference at most.)                                                                                                                                                                                                                                                                                                                        |

**Bottom line:** stay on **LVGL 9.2.2** (already in `managed_components/lvgl__lvgl`) with the existing `Arduino_GFX` NV3041A path. The redesign is a **theme + layout + wording** effort, not a driver/framework migration.
